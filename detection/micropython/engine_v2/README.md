# engine_v2: machine-at-the-pile detector for the LoPy

PC tooling and device code for the v2 detector that replaces the burst MLP in
`deploy/burst/main.py`. The deployable firmware is `deploy/v2/main.py`, generated by
`build_main.py`. The full validation report (in Polish, with figures) is `RAPORT_v2.html`.

## What runs on the LoPy

The device wakes up on GPIO (P19 microphone comparator or P20 vibration), records 10 one-second
blocks at 4 kHz with the existing `nagraj_audio()`, and scores the session:

1. Per block: four Hann frames of 512 samples (as burst), Welch-averaged power spectrum.
2. Per block features: 15-band spectral shape, whitened log spectrum (log P minus its local
   mean over +-12 bins), harmonicity, flatness, sub-frame envelope variation, low/high ratio,
   frame-to-frame line correlation, impulse rate, level.
3. Session vector (57 values, `features.NAMES`): means and spreads over blocks plus the
   line-persistence features (correlation of the whitened spectrum between consecutive and
   every-other blocks, number and persistence of strong lines below 500 Hz) and level
   variation (gusts).
4. MLP 57-8-1 with int8 weights -> logit.
5. Decision (`main()`):
   * logit >= `V2_T_HIGH` -> ALARM now;
   * logit >= `V2_T_SUSP` -> store a flag in NVS, deep sleep 2 min (timer), record a second
     session; ALARM if that one is >= `V2_T_SUSP` too;
   * vibration wake + suspicious session -> ALARM now;
   * otherwise back to GPIO sleep.

All features are ratios or correlations, so the microphone gain does not change the result
(tested). `v2_bench()` in `main.py` prints ms per block and free heap on the board.

## Files

| File | Role |
|---|---|
| `devsim.py` | WAV reading, device-domain simulation (mic high-pass, 4 kHz decimation without anti-alias filter, 12-bit ADC), dataset indexes |
| `cache.py` | renders all sessions at three gains (+ engine/weather mixtures) to `$TG_DATA/cache/sessions_<tag>.npz` |
| `features.py` | numpy reference of the session features (the oracle) |
| `tg_v2_device.py` | the same features in MicroPython v1.11-compatible Python + MLP scoring |
| `feat_cache.py` | session feature matrix for a cache tag |
| `train_eval.py` | logistic / MLP / boosted-tree models, source-disjoint cross-validation, reports |
| `export_model.py` | trains the deployed MLP, picks thresholds from out-of-fold decisions, writes `model_v2.json` |
| `build_main.py` | builds `deploy/v2/main.py` from `deploy/burst/main.py` + `tg_v2_device.py` + `model_v2.json` |
| `firmware_runner.py`, `eval_firmware.py` | run any standalone `main.py` on PC with mocked Pycom modules |
| `eval_wake.py` | two-session confirmation metrics |
| `fsd50k_extract.py` | extracts the held-out FSD50K clips from the split archive |
| `test_v2_device.py` | parity (device code vs numpy, 1e-4), gain invariance, `main.py` logit parity, wake state machine |

## Reproduce

Python 3.12 and numpy only.

```bash
cd detection/micropython
python3 -m venv .venv && .venv/bin/pip install "numpy>=2.1,<3"
cd engine_v2
../.venv/bin/python -m unittest test_v2_device
```

Data go to `$TG_DATA` (default `~/tg-data`); download commands and SHA-256 sums are listed
in `RAPORT_v2.html`, section "Dane". Then:

```bash
../.venv/bin/python fsd50k_extract.py
../.venv/bin/python cache.py v4
../.venv/bin/python feat_cache.py v4
../.venv/bin/python eval_firmware.py ../deploy/burst/main.py v4   # baseline
TG_TAG=v4 ../.venv/bin/python export_model.py
../.venv/bin/python build_main.py
../.venv/bin/python make_report.py
```

## Known limits

* No recording from our microphone and ADC exists yet; the device chain is simulated.
* LoPy run time and heap are not measured; run `main.v2_bench()` on the board.
* Log impacts during loading are not detected separately; the vibration input only raises
  confidence and lets a suspicious session alarm at once.
