# Timber Guard v2: обнаружение подозрительной погрузки древесины

Рабочий исследовательский прототип для **отдельного анализа аудио (WAV/MP3)**, **отдельного анализа вибраций / акселерометра** и **Sensor Fusion**. Основа: извлечение признаков, пороговые правила, временное накопление событий. Нейросетей и облачных сервисов нет.

**Ограничение:** распознавание *характерного звука двигателя* не равно достоверному определению грузовика. Срабатывание означает подозрительную активность, а не доказанную кражу. Пока нет собственных полевых данных и подтверждённого контакта вибраций со штабелем, показатели точности неизвестны.

## 1. Быстрый старт (Windows, PowerShell, VS Code)

В корне распакованного проекта (где лежит папка `detection`):

```powershell
py -m pip install -r requirements.txt
py -m detection.app.main demo
```

Поддерживается Python 3.10+. В `requirements.txt` используется `imageio-ffmpeg`, поставляющий FFmpeg автоматически: отдельно устанавливать FFmpeg для MP3 не требуется.

Команда `demo` генерирует тестовые записи (`detection/results/demo/raw_demo`) и запускает **три** режима. Результаты сохраняются **внутри проекта**, независимо от текущей рабочей папки.

```
Detektor-kradziezy-drewna/
  detection/
    app/main.py
    core/...
    data/demo_data.py
    results/
      demo/
        raw_demo/calibration/{microphone.wav,sensors.csv}
        raw_demo/scenario/{microphone.wav,sensors.csv}
        audio/{features.csv,predictions.csv,result.png,summary.json,model.json}
        vibration/{features.csv,predictions.csv,result.png,summary.json,model.json}
        fusion/{features.csv,predictions.csv,result.png,summary.json,model.json}
      custom/
        audio/...
        vibration/...
        fusion/...
```

Можно просто запустить `run_demo.bat` двойным щелчком (если Python доступен как `py`). Для собственных WAV/MP3 можно **перетащить файл на `analyze_audio.bat`**, и он запустит звуковой анализ без ввода команды (после первоначальной установки зависимостей).

## 2. Проверка на своём WAV/MP3 БЕЗ датчиков

```powershell
py -m detection.app.main analyze --mode audio --audio "C:\Recordings\truck.mp3"
```

или

```powershell
py -m detection.app.main analyze --mode audio --audio "C:\Recordings\truck.wav" --out "detection/results/experiment_01"
```

В архиве также лежит демонстрационный MP3. Его можно проверить без поиска аудио:

```powershell
py -m detection.app.main analyze --mode audio --audio "detection/sample_audio/truck_loading_demo.mp3"
```

Результаты: `detection/results/custom/audio/` (или `experiment_01/audio/`).

- `result.png`: **осциллограмма**, **спектрограмма**, график RMS с порогом, доля низких частот с порогом, показатель коротких ударов с порогом и выделенные интервалы двигателя.
- `predictions.csv`: временные окна со всеми значениями и состояниями `BACKGROUND`, `ENGINE_SOUND`, `AUDIO_IMPACT`, `ENGINE_AND_AUDIO_IMPACT`.
- `features.csv`: извлечённые показатели (без классификации).
- `summary.json`: количество обнаруженных окон, пороги и прочая информация.
- `model.json`: параметры выбранной калибровки.

**Важно:** микрофон отдельно никогда не выдаёт тревогу о краже (`alarm=0`). Он умеет находить акустические признаки, которыми потом можно воспользоваться при совместной проверке.

## 3. Только датчики

В `sensors.csv` нужны секунды `time_s` и **как минимум один** тип датчиков:

```csv
time_s,accel_x,accel_y,accel_z,vibration
0.00,0.001,0.002,1.001,0.015
0.01,0.003,0.001,1.004,0.017
0.02,0.005,0.002,1.009,0.022
```

Допустимы файлы только с `time_s,vibration` или только с `time_s,accel_x,accel_y,accel_z`.

Команда:

```powershell
py -m detection.app.main analyze --mode vibration --sensors "C:\Recordings\sensors.csv"
```

График: RMS и пики вибрации, динамика акселерометра, окна обнаруженных механических импульсов. `alarm=0`, поскольку без акустики совпадение обоих критериев не проверено.

> Вибрационный датчик с бинарным выходом 0/1 может требовать другого извлечения признаков: данный прототип рассчитан в первую очередь на аналоговые амплитуды. Столбцы акселерометра должны иметь согласованные единицы измерения (например, g) в фоне и эксперименте.

## 4. Вместе: два критерия (Sensor Fusion)

```powershell
py -m detection.app.main analyze --mode fusion --audio "C:\Recordings\truck.mp3" --sensors "C:\Recordings\sensors.csv"
```

Чтобы **одной командой протестировать все три режима** и получить отдельные графики/таблицы:

```powershell
py -m detection.app.main analyze --mode all --audio "C:\Recordings\truck.mp3" --sensors "C:\Recordings\sensors.csv"
```

`--mode all` создаёт подпапки `audio`, `vibration`, `fusion`.

**Синхронизация критична:** `time_s=0` в CSV должен соответствовать **началу звукового файла**. Если датчики записывались с задержкой относительно начала аудио, передай, например, `--sensor-offset 2.5` (прибавляет 2.5 сек ко всем временам датчиков). Отрицательные значения тоже поддерживаются.

В режиме `fusion` возможны состояния:

- `BACKGROUND`: ни одного условия.
- `ENGINE_ONLY`: подтверждён характерный низкочастотный звук, но нет нужных ударов.
- `MOTION_ONLY`: есть вибрация без подтверждённого двигателя.
- `POSSIBLE_LOADING`: двигатель обнаружен недавно **И** есть не менее 2 независимых вибрационных импульсов за интервал наблюдения. Тревога (`alarm=1`) не повторяется чаще заданного времени ожидания.

Несколько соседних перекрывающихся окон с одним ударом считаются одним импульсом (по фронту срабатывания). Звуковые удары учитываются как дополнительная диагностическая информация, но **не заменяют механическую вибрацию**.

## 5. Калибровка на собственном тихом фоне (рекомендуется)

Без отдельного фона программа оценивает пороги по самым тихим 30% окон **самой записи** плюс фиксированные минимумы. Это удобно для эксперимента, но может ошибаться на долгом непрерывном шуме двигателя, тихих записях и при других масштабах амплитуд. Такой режим подписан `heuristic_low_30pct`.

Гораздо надёжнее отдельно снять фоновые записи с той же расстановкой датчиков:

```powershell
py -m detection.app.main calibrate --audio "C:\Recordings\quiet.wav" --sensors "C:\Recordings\quiet_sensors.csv"
```

Будет создан `detection/results/quiet_model.json`. Потом запустить:

```powershell
py -m detection.app.main analyze --mode all --audio "C:\Recordings\truck.mp3" --sensors "C:\Recordings\sensors.csv" --model "detection/results/quiet_model.json"
```

Или сразу подать фоновую запись в `analyze`, без отдельной команды:

```powershell
py -m detection.app.main analyze --mode audio --audio "C:\Recordings\truck.mp3" --baseline-audio "C:\Recordings\quiet.wav"
```

Для `fusion` можно указать **оба** аргумента: `--baseline-audio`, `--baseline-sensors`. Если один из них отсутствует, алгоритм применит эвристическую калибровку для недостающего типа сигнала и явно укажет это в `summary.json`.

Не следует калибровать модель на записи, которая уже содержит погрузку, поскольку это повысит пороги и испортит чувствительность.

## 6. Как именно работает алгоритм

1. **Аудио:** FFmpeg приводит WAV/MP3 к моно 8 кГц. Анализ окнами по 2 сек с шагом 1 сек. Рассчитываются громкость RMS, доля мощности на 40–250 Гц в диапазоне 35–3500 Гц, и отношение самого сильного 50-мс участка к медианной энергии участков (звуковой импульс).
2. **Аудио-порог:** `audio_rms > порог` **и** `audio_low_ratio >= 0.48` означает окно с характеристиками двигателя. Три последовательных окна подтверждают двигатель; после него действует память 18 сек.
3. **Вибрация:** на каждом окне удаляется среднее значение вибрационного сигнала и постоянная составляющая ускорения, затем рассчитываются RMS и максимумы. Вибрационный канал или акселерометр должны одновременно пересечь свои пороги RMS и пика.
4. **Sensor Fusion:** если за последние 14 сек произошло минимум два отдельных механических импульса, а двигатель был недавно подтверждён, появляется `POSSIBLE_LOADING`. Пауза между уведомлениями: 15 сек.

Эти параметры находятся в `detection/core/detector.py`, класс `Settings`. При желании можно изменить окно через `--window-s 2 --hop-s 1` на командах `analyze` и `calibrate`. При использовании `--model` размеры окон должны совпадать с сохранённой моделью.

**Известные ограничения:** низкочастотный гул возможен не только у грузовика (генераторы, промышленный шум, музыка); удалённые от брёвен датчики могут совсем не зафиксировать погрузку; недостаточно синхронизированные каналы делают fusion ненадёжным; нет классификатора фактической кражи, только правила для подозрительной активности. Реальные данные необходимы для оценки ложных тревог и пропусков.

## 7. Тесты

```powershell
py -m unittest discover -s tests -v
```

Тестируются чтение WAV и MP3, независимые режимы, fusion и синхронизация. Для MP3 в тесте используется FFmpeg из `imageio-ffmpeg`.

## Полезные параметры

```powershell
py -m detection.app.main --help
py -m detection.app.main analyze --help
```

`--out` - директория эксперимента, под ней автоматически появится имя режима. По умолчанию **`detection/results/custom/`**. Сохраняй отдельные эксперименты через разные `--out`, чтобы не перезаписывать предыдущие результаты.
